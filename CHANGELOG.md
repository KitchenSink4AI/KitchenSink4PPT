# Changelog

### 2.0.0

KitchenSink4PPT 2.0 regroups the tool surface. Read the breaking changes first, then [`docs/surface_map.md`](docs/surface_map.md), which lists every 1.3.1 tool beside its replacement.

**Breaking changes**

- **Nine grouped tools replace the 142 flat tools of 1.3.1.** The tools are `ppt_deck`, `ppt_design`, `ppt_edit`, `ppt_graphics`, `ppt_help`, `ppt_inspect`, `ppt_read`, `ppt_review` and `ppt_tables`. Each takes `{op, args}`, and 145 operations sit behind them. A call that used to be `svg_to_shapes(...)` is now `ppt_graphics` with `op: "svg_to_shapes"`. Every released operation survives except the two below; some arguments changed, so check `ppt_help` for an operation before the first call. The `migrate-from-v1` recipe in `get_workflows` and `migration/v1_to_v2.json` carry the same routing map.
- **`enable_tools` and `disable_tools` are gone.** Every operation is present from the start, and the whole surface costs about 7.3k tokens at startup. Their rows in the map have no target.
- **The pack settings are retired.** An old default (`KS4P_MODE=lite`, `full` or `everything`, `KS4P_PACK_POLICY=auto`, `KS4P_ALL_TOOLS` on or off, `KS4P_LOCK_TOOLS` off) no longer stops an upgrade: the server starts with every tool listed, one line on stderr names the ignored settings and the status report lists them. A setting that locked the tools (`KS4P_PACK_POLICY=locked`, `KS4P_LOCK_TOOLS` on or a `KS4P_MODE` list of packs) stops startup with a message naming what to use instead: `KS4P_READ_ONLY` and `KS4P_FORBID`.
- **Arguments are validated.** `ppt_help` returns the arguments and a worked example for any operation, and an unknown argument is refused by name instead of dropped.
- **`slide_count` is always the number of slides in the deck.** In `get_text` and `get_presentation_view`, a read with a `scope` used to give the number of slides the scope selected as `slide_count`. That number is now `slides_in_scope`, and `slide_count` means the same thing in every answer.
- **Snapshots go into the deck's hidden backup folder.** `create_snapshot` used to write `YYYYMMDD_HHMM_<name>.pptx` beside the deck, so in a folder where the newest leading date stamp marks the current version, every snapshot looked newer than the deck it came from. A snapshot now goes into the deck's hidden `.ks4p-backups` folder, where `manage_backups` lists it and restores from it and nothing rotates or purges it. With `dest_dir` it is a visible copy named after the deck, `<deck name> (snapshot <label> YYYY-MM-DD HHMM).pptx`, so it never carries a newer leading date stamp than the deck. The time in the name and the file's modification time are both the time the copy was written, and the answer gives the full path and says whether the copy is hidden. Copies that earlier versions left beside a deck are not moved.
- **Exports never replace a file unless the call sends `overwrite=true`.** `export_pdf`, `export_handout`, `export_slide_image`, `export_table` and `export_shape_image` refuse an existing output before anything starts, and the refusal names it. To render into the same folder again, send `overwrite=true`. The exports are now marked as not destructive.
- **Comments are signed with your own name.** When a call to `add_comment` or `reply_to_comment` names no author, the comment is signed with your Office user name and initials, or your Windows sign-in name when Office has none. It used to be signed "KitchenSink4PPT". Set `KS4P_AUTHOR=assistant` to sign "AI Assistant via KS4PPT" instead, or ask for it in one call with `author="assistant"`; `KS4P_COMMENT_AUTHOR` still names an author outright, and any other author named in the call is used as given. An email address never signs: one sent as `author` or set in `KS4P_COMMENT_AUTHOR` is set aside, the next choice signs, and the answer says so. The same holds for the deck's author and last-modified-by properties (`set_document_properties`) and for `anonymize_deck`'s replacement, where its default name stands in. Each answer says where the name came from in `author_source`, and an unknown `KS4P_AUTHOR` stops the server from starting with a plain message.
- **A document type declaration is refused, in a deck or in an SVG.** A deck whose XML holds a `<!DOCTYPE ...>` in any part is refused before anything is read, with `UNSUPPORTED_CONTENT` and a sentence that names the part. PowerPoint never writes one: it refuses such a deck, or repairs it by dropping the part. Such a deck used to open here, a small entity it declared was read as slide, notes, chart or comment text, and an edit saved the declaration back into the file. `validate` reports the refusal and does not ask PowerPoint to open the file. `svg_to_shapes` refuses an SVG whose `<!DOCTYPE>` carries declarations of its own, before anything reads it; to convert one, remove the bracketed block and write each `&name;` reference out. The SVG 1.1 header, which only names a DTD, is dropped and the drawing converts as before.
- **A bare integer placeholder selector on a master or layout now means the placeholder's `idx`.** In 1.3.2 it meant a shape id on `set_master_placeholder`, `set_layout_placeholder` and the other master and layout operations, unlike `set_placeholder_text`. A saved call that passes a shape id as a bare integer must send `{"shape_id": 5}` instead; an `idx` shared by two placeholders is refused with both listed.

**Added**

- **Update notices.** At most once a week, after you use a tool, the server checks PyPI in the background. When a newer version exists, your AI app shows a short notice with Update now and Not now, if the app supports one and the server runs through uvx or the Claude Desktop extension. Otherwise your AI mentions it once and can update it for you if you agree (`ppt_review` `update_now`). It never downloads or installs a new version unless you choose Update now in its notice or ask your AI to update it. Update now refreshes a `uvx` install, or downloads and checks the new Claude Desktop bundle and opens Desktop's own install window; a `pip` or `uv tool` install gets the exact command to run. `update_notices` turns the notices on or off from any app, `KS4P_UPDATE_NOTICES=off` turns them off and `KS4P_UPDATE_CHECK=off` turns the check off. `kitchensink4ppt --version` prints the installed version. The Claude Desktop extension passes one setting, `KS4P_INSTALL_ROUTE=mcpb`, which tells the server it runs from the bundle.
- **`slide_number` names a slide the way people count.** Every operation that takes `slide`, and every edit in `apply_edits`, also takes `slide_number`, which counts from 1, so the slide a user calls slide 2 is `slide_number` 2. `slide` still counts from 0. Each tool's description of its arguments states the rule, and `ppt_help` lists `slide_number` beside `slide`. Where `slide` is required, the `ppt_help` schema requires `slide` or `slide_number`, so a client that checks calls against the schema accepts either. `slide_number`, `slide_index` and `slide_id` sent as null count as not sent, like every other optional argument, and the `ppt_help` schema allows a null `slide_number` beside `slide`. On its own, a null `slide_number` names no slide, and both the server and the schema refuse it.
- **Every answer about one slide says which slide it is.** It starts with `slide_number`, `slide_count` and `slide_title`, also on a refusal that came after the slide was found. `slide_count` is the deck after the call: `delete_slide` names the slide it removed as `deleted_slide_number`, and `duplicate_slide` and `copy_slide_between` name the slide they copied as `source_slide_number`. When the slide was named by `slide` or `slide_index`, which count from 0, a `slide_note` says in words which slide that was, for example "the third slide, not the second (slide_number 3 of 4)". An assistant that sent the user's own number to `slide` can see that it got the next slide. A read whose `scope` names one slide starts the same way.
- **Every argument that counts slides says how.** `ppt_help` describes `to_slide`, `to`, `position`, `order`, `slides`, `from_slide`, `to_slides`, `scope`, the `ranges` of `split_deck` and the `section` of `manage_section` as counting from 0, like `slide`. The show range of `set_show_properties` counts from 1, and its description says so.
- **`set_hyperlink` names the slide a jump link goes to** as `target_slide_number` and `target_slide_title`, beside the 0-based `target_slide`.
- **Two editions on one core.** Community (AGPL-3.0, the `kitchensink4ppt` command) and Business (`kitchensink4ppt-business`, with a `+business` build suffix) share the same editing core, so safety, backup and document integrity behave identically. Business checks its license receipt locally and never calls the public update endpoint. `get_server_info` reports the edition and the verification status; `include_licensee` adds the licensee's company name on request.
- **Bullets on text boxes get a default hanging indent.** Setting the indent to `none` clears it, and `space_before` and `space_after` are available.
- **`create_presentation` reports the sensitivity label and core properties it inherits from the template.**
- **A default template ships with the package; its notice is listed in `NOTICE.md`.**
- **An answer can carry `notices`.** When the recovery from a stopped save leaves something for you to look at, such as an older copy kept beside a deck, the next answer lists it under `notices`, once in each run of the server.
- **`set_shape_adjustments` reads and sets a preset shape's adjust handles by name.** Called with only the shape, it lists every handle of the shape's preset with its value and default. `adjustments` sets handles by name, and a value with a decimal point is a fraction, as `insert_shape` reads it; `degrees` sets an angle handle, such as an arc's start and end, in degrees. Every write stores the whole list of the preset's handles in its own order: the handles you send, and for each other handle the value it already had, or its default. A handle name the preset does not have is refused.
- **`insert_shape` can put a new shape inside an existing group.** `group` names the group; `x` and `y` stay slide positions, and the group's frame grows to hold the shape. A group's frame also follows its members when `set_shape` moves or resizes one, so nothing else on the slide moves. A rotated or flipped group is refused for an insert, and left as it is, with a warning, when a member changes.
- **`set_shape` can scale text and lines with a resize.** With `w` or `h`, `scale_text` scales every font size, text inset and point spacing inside the shape or group, and `scale_lines` scales every outline width, both by the smaller of the width and height ratios, so text that fitted still fits. `no_wrap` keeps each paragraph of the text boxes inside on one line. Tables and charts inside a scaled group are named in a warning and not scaled. All three are off by default. A `w` or `h` of zero is refused with `scale_text` or `scale_lines`, because it would shrink every size to nothing; leave a side out to keep it.
- **`copy_shape_between` copies a shape or a group from a slide of another deck, or of the same deck.** Pictures, charts, tags and links come with it, and connector glue follows the copied shapes. Between decks with different designs, the theme colors, theme fonts and inherited text sizes are written out from the source, so the copy keeps its look. `leave_out` drops members of a copied group, which is refitted to what is left; `w` or `h` alone keeps the proportions; `scale_text`, `scale_lines` and `no_wrap` work as on `set_shape`. Placeholders, SmartArt, embedded objects, ink and links into another deck are refused with the reason.
- **`export_shape_image` renders one shape or group to a PNG** at a set width or height. The image covers the area the shape is drawn in, through its groups, with its rotation and outline, clipped to the slide. It needs PowerPoint, and Pillow (the `optimize` extra). When `KS4P_ALLOWED_ROOTS` is set, the slide it cuts the shape from is rendered in the server's own temporary folder; the deck and the output must still be inside the allowed folders.
- **Every argument that counts slides from 0 has a twin counted from 1**, except the `scope` of `set_footer`, whose own `slide_number` turns slide numbers on. The twins are `from_slide_number` and `to_slide_numbers` (`copy_position`), `order_numbers` (`reorder_slides`), `number_ranges` (`split_deck`), `to_slide_number` (`set_hyperlink`), `to_number` (`move_slide`), `position_number` (`insert_slide`, `duplicate_slide`, `copy_slide_between` and `generate_agenda_slide`), `source_slide_number` (`copy_shape_between`), and `slide_number` or `slide_numbers` for the `scope` of `get_presentation_view`, `get_text`, `find_text`, `list_elements`, `list_hyperlinks`, `list_equations`, `list_comments`, `audit_accessibility` and `search_and_replace`. Sending both forms is refused with a hint.
- **Speaker notes for many slides in one save.** `apply_edits` takes a `set_notes` edit, and `set_notes` takes `notes`, a list of entries, each with `slide_id` or `slide_number` and `text` or `paragraphs`. Every slide is checked before anything is written, so one bad entry leaves the deck unchanged, and the whole list is one backup and one save. Each entry names its slide by `slide_id` or `slide_number`; a `slide` counted from 0 on its own is refused, and so are two entries for one slide. The list works on a deck that is not open in PowerPoint; for an open deck, set one slide's notes at a time.
- **Paragraph edits in `apply_edits`.** `set_paragraph`, `insert_paragraph` and `delete_paragraph` change one paragraph of a shape, named by `paragraph`, counted from 0 as `find_text` reports it, or by `paragraph_number`, counted from 1. Every paragraph address in one batch counts the shape's paragraphs as they were before the batch. A changed paragraph keeps its look, and a new paragraph takes the look of the paragraph now in its place, or of the last paragraph when it goes at the end. A shape keeps at least one paragraph, and edits that would make an address unclear, such as two edits to one paragraph, are refused before anything is written.
- **`search_and_replace` can remove the paragraphs it empties.** With `remove_empty_paragraphs`, each paragraph that a replacement leaves with nothing but spaces and line breaks is removed, in slide text and table cells (and in notes when `include_notes` is true), and `paragraphs_removed` counts them. Paragraphs that were empty before the call stay, every text body keeps one paragraph, and SmartArt is left as it is. It works on a deck that is not open in PowerPoint.
- **A scope can be a range of slides.** Every `scope` that selects slides takes a range such as `{"start": 1, "end": 3}`, counted from 0 with both ends included, on its own or in a list, and `slide_numbers` takes the same range counted from 1. A range outside the deck is refused with the deck's range.
- **The argument names a model tries first are read.** `shape_id` is read as `shape` on every operation that takes `shape`; `font_size` is read as `size_pt` on `format_text` and `insert_textbox`, and as `size` on `set_master_placeholder` and `set_layout_placeholder`; `slides` is read as `scope` on the operations whose `scope` selects slides. In `apply_edits`, `shape_id` works on the edits that address a shape and `font_size` on `format_text`. The answer's `normalized_from` says which name was read as which, and two names sent with different values are refused.
- **`find_text` takes `match_case`.** It matches exact case by default, as before, and `match_case=false` finds any case. When an exact-case search leaves out matches that differ only in case, the answer's `case_note` says how many, which spellings, on which slides by `slide_number`, and that `match_case=false` includes them.

**Changed**

- **A slide index past the end is refused with both ranges, 0 to N-1 for `slide` and 1 to N for `slide_number`.** A slide can also be named by `slide_index` or `slide_id`, and a slide sent as text, such as `"1"` or `'{"slide_id": 257}'`, is read as the number or id it holds. Two names that disagree are refused.
- **`insert_slide`, `duplicate_slide` and `move_slide` report `new_slide_number`, the slide's position counted from 1, and each `apply_edits` result carries the `slide_number` it changed.**
- **The startup banner of the framework underneath is switched off, so that framework's own version check cannot contact PyPI.** The server's own update check is separate; see Update notices under Added.
- **`compress_deck` purges unused parts only when asked, and `apply_brand` takes the font keys it documents.** `purge_unused` now defaults to `false`, so a plain `compress_deck` shrinks images and leaves unused layouts, orphaned notes pages and unreferenced media in the deck; `purge_unused=true` removes them. Without Pillow, a compression that has images to shrink now refuses with a pointer to the `[optimize]` extra before it changes anything, where it used to skip the images and run only the purge, and `dry_run` still lists each image as `skipped-no-pillow`. `apply_brand` accepts the flat font keys `major_latin`, `minor_latin`, `major_ea` and the like beside the nested form, and refuses an unknown font key by name before anything is written.
- **`export_table` writes CSV files with a byte-order mark, so Excel reads them as UTF-8.** Accented letters and Korean, Japanese and Chinese text arrive as written. `import_table` reads the file with or without the mark, and the JSON export is unchanged.
- **A notes master that `set_notes` creates uses a plain light theme, so notes pages stay readable under a dark slide theme.** When a deck had no notes master, `set_notes` used to copy the first slide master's theme into the new one, and a deck with dark slides got a dark notes page with light text. The new master now keeps that theme's structure but takes a black-on-white color scheme and the Aptos fonts. A deck that already has a notes master is not changed.
- **`set_theme_fonts` reports the text it cannot change.** A run that carries a typeface of its own keeps it when the theme fonts change. The answer now counts those runs in `explicit_font_run_count`, lists them by slide under `explicit_font_affected_slides` with each typeface and how many runs use it, and adds a warning when the count is not zero. Text that follows the theme's font, such as the body font, is not an override and is not counted. The count covers the slides that use the selected master.
- **`list_elements` reads `type` as `kind`, and `normalized_from.hint` says the argument is named `kind`.**
- **A list of slides can be counted from 1.** `export_slide_image` and `manage_custom_show` take `slide_numbers`, counted from 1, in place of `slides`, which still counts from 0. Sending both is refused with a hint. Each slide in their answers carries `slide_number` beside the 0-based index, so an image's `slide_number` matches its `slideN.png` name.
- **A shape can be named, not only numbered.** `set_shape`, `set_shape_adjustments`, `format_text`, `fit_text`, `set_bullets`, `get_autofit_state`, `add_equation_to_shape`, `copy_shape_between` and `export_shape_image` take a shape's id (digits as text too), its name, a path such as `"Group/Shape"` for a shape inside a group, or the anchor `get_presentation_view` prints (`a:3f9c2a`, brackets optional), and `insert_shape` takes its `group` the same way. A name that more than one shape carries is refused, and the refusal lists each one with its id and group; an anchor of a shape on another slide is refused with the slide it is on. Other operations that take a shape still take its id.
- **Read answers that list slides give each slide's `slide_number`.** `get_text`, `extract_text`, `list_elements`, `list_comments`, `get_transitions`, `get_autofit_state` over the whole deck, `deck_statistics` and the findings of `check_layout` carry `slide_number`, counted from 1, beside each slide's 0-based index.
- **`ppt_help apply_edits` lists the edits it can batch,** with each one's fields, how it names its target and an example, generated from the edits `apply_edits` accepts. `ppt_help set_text` points to `apply_edits`, and the help of an operation that also batches says so.
- **`manage_backups` reads `slot` as `source`.** Every listed slot carries the `source` that restores it, as snapshots already did, and a slot name is read in any case. `slot` and `source` sent with different values are refused, naming both; the same holds for the other argument synonyms.
- **A deck that is open in PowerPoint can be read.** The operations that only read a deck used to refuse it as locked. They now read the file as last saved and say so in `open_deck_note`: changes made in PowerPoint since the last save are not included. `get_text` and `get_slide_info` with `live='auto'` read the open copy, unsaved changes included, and read the saved file, with the reason in the note, when the open copy cannot be reached. If PowerPoint is writing the deck at that moment, the read tries again briefly and is then refused with `DOCUMENT_LOCKED` and a hint to retry. Changes with `live='off'` are still refused while PowerPoint has the deck open, and with `live='auto'` they still go to the open copy. This covers the operations that only read: exports, `split_deck`, `copy_presentation` and the copies between decks treat a source deck that is open in PowerPoint as before.
- **`export_slide_image` says how it counts.** Its description says `slides` counts from 0 and names `slide_numbers` and `width`. Each image record now starts with its `slide_number`, and an answer to a call that sent `slides` carries `slides_note`, which says which slides were rendered, counted both ways.
- **`ppt_help` says what `set_text` does to formatting.** On a shape whose paragraphs are formatted differently, new paragraph N takes old paragraph N's formatting, extra new paragraphs take the last old paragraph's, and a paragraph whose runs differed takes its first run's look, which the answer reports as `runs_collapsed_to_first`. To change one paragraph and keep the others as they are, use the paragraph edits in `apply_edits`.
- **Every `apply_edits` edit takes `slide_id`** beside `slide` and `slide_number`, and `format_text` in a batch takes `paragraph_number`, counted from 1.
- **Deleting the shape or slide with the highest id says that the id will be used again.** `delete_shape`, `ungroup_shapes` and `delete_slide` warn that the next new shape or slide will take that id and answer to the old view anchor. PowerPoint numbers new shapes and slides the same way.
- **`search_and_replace` says what it left in another case.** With `match_case` true, the default, it never changes text in another case, and `case_note` now says how many such matches it left and on which slides. `apply_edits` and the live route say it too. A match inside an equation is not counted there, because no replace changes it; `wrapped_matches_skipped` counts it.
- **Text reads show an equation or newer text inside a paragraph.** `get_text`, `get_table`, `get_notes`, `extract_text`, `find_text` and `get_presentation_view` include an equation that sits in a paragraph, such as one `add_equation_to_shape` or `insert_equation` wrote, as its characters, and text written in a paragraph for a newer PowerPoint version, as PowerPoint shows it. `search_and_replace` leaves a match inside an equation as it is and counts it in `wrapped_matches_skipped`. An edit that would rewrite or flatten such content, such as a format range across it, `set_paragraph` in `apply_edits` or a plain `set_notes`, is refused with the next step. `list_equations` lists each equation in a shape's text, a table cell or the speaker notes, with where it is.
- **`list_hyperlinks` reads links in more places.** It lists links in table cells, on fields such as a slide number, in speaker notes, in SmartArt, and on the layouts and masters the listed slides use. It reports click actions that have no address: running a custom show (flagged when the deck has no such show), running a macro, and an object action, and a link that runs a program or opens a file says so. A click that only plays a sound is listed as kind `sound`, and an action that also plays one names it. `set_hyperlink` and `remove_hyperlink` still reach the links on shapes and their text.
- **Video and audio are typed `media`.** `get_slide_info` and `list_elements` used to type a video or an audio clip as a picture; they now say `media`, as the live route did, and `images` lists pictures only. The accessibility audit, the contrast check and the view treat media as they treat pictures.
- **A change is no longer refused for a problem the deck already had.** If a deck arrives with, for example, an unused link to a picture that is gone, or a part nothing refers to, edits now save, the problem stays as it was, and the answer's `warnings` name it. A problem the change itself would add is still refused, and restoring a backup follows the same rule. `validate` still reports every problem it finds.
- **A long answer says how much it holds before the bulk of it.** A client may show only the first 2,000 characters of a long answer. An answer longer than that now starts with the slide it is about, if any, then `ok`, `file` and the `page` block (the true total, how many came back, whether the answer was cut and the `next_offset` that continues it), then its counts and notes, then its long lists and texts. A short answer is unchanged.
- **Clearer refusals.** A slide sent as `slide_number` is named by that number when it is out of range. An argument that needs a closed deck says the deck itself is fine. A deck under a folder named like a device (`con`, `nul`, `com1` and so on), which PowerPoint cannot open, is named as the cause instead of being called damaged. A deck whose slide ids reached 2147483647, the highest the file format allows, is refused with what happened and how to continue: `merge_decks` into a new deck numbers the slides afresh. Its hint says the same, instead of asking for other arguments.
- **Edits to a deck open in PowerPoint stay unsaved for you to review.** The server instructions and `live_save` say a save is made only when you ask for it. `live_save` also answers `unsaved_before_our_edits`: `true` when the deck already had unsaved changes before this server's first live edit to it, `false` when it did not (typing you did after that first edit is not told apart from the edit), and `null` when that is not known, for example when the server made no live edit to it since the deck was last clean. A save you make between two of the server's edits starts a new record. When the answer is `true` or `null` and the deck had unsaved changes, a `save_note` says what that means for the save.

**Fixed**

- **A deck's lock no longer outlives the server that held it.** If a server released its lock on a deck while another server was checking that lock, the lock file could stay behind. Other servers were then refused that deck, or for live edits kept waiting for PowerPoint, until the first server exited. The release now retries, and a lock file it could not remove is removed as soon as it can be. Each leftover is cleaned up on its own record, so clearing an old one cannot drop the cleanup of a newer one on the same deck.
- **Two servers can no longer both take a lock left behind by a server that died.** If a server died holding the lock on a deck, two servers waiting for it could each decide it was abandoned. The slower one then deleted the lock the faster one had just taken, and both saved into the same deck, so one change could silently replace the other. A waiting server now breaks a dead lock one at a time, and only while it is still the lock that server judged abandoned. The lock that serializes live PowerPoint sessions is broken the same way.
- **A saved change keeps the deck's Mark of the Web, permissions and creation time.** Every save replaced the deck with a new file. That dropped the Mark of the Web that Windows puts on a downloaded file, so after one edit the deck opened in PowerPoint without Protected View, and it dropped the deck's own permissions, which fell back to those of its folder, and its creation time. On Windows the save now swaps the new version in with ReplaceFile, which keeps all three along with the file's attributes. Restoring a backup and overwriting a deck with `copy_presentation` do the same. Where a file system has no ReplaceFile, the Mark of the Web, creation time and attributes are put back by hand, and the deck takes the folder's permissions, which the answer says in a warning when the deck had permissions of its own. A program that has the deck open and shares delete no longer stops a save. Other programs may see the deck missing for a moment during a save, usually a few milliseconds; this server's reads wait it out. In a folder where people may change files but not their permissions, the save still keeps the Mark of the Web, creation time and attributes, and a deck whose own permissions cannot be kept there takes the folder's, which the answer says in a warning. If the new version cannot be moved into place, the answer is `DOCUMENT_LOCKED` and the deck is unchanged. In the rare case that the deck cannot be put back in its place either, the answer is `CONFLICT` and names where the deck is kept. If the server is stopped in the middle of a save, the deck is not lost: it is kept beside its path under a name that starts with `.ks4p-replaced` and ends `(as it was before a save).tmp`. The next change to the deck, or the next start of a server that may change files, puts it back, and a read in the meantime says where it is.
- **A refused save or restore no longer costs the undo of the last change.** When another program held the deck and a save was refused, the backup of the version before the last change had already been replaced, so a `manage_backups` restore of `prev` answered ok and changed nothing. The backups are now updated only after the new version is in place, so a refused save, restore or copy leaves them as they were. A restore whose backup already matches the deck says so instead of answering ok.
- **A change refused because another program holds the deck stays a file answer.** With `live='auto'`, a save refused by an antivirus, sync client or viewer holding the deck went looking for the deck in PowerPoint and answered `APP_NOT_RUNNING`. It now answers `DOCUMENT_LOCKED` and says what to close before retrying. A deck that is open in PowerPoint still goes to the open copy.
- **A save stopped in its last instant no longer brings back an older copy.** A server stopped after a save had moved the new version in, but before it tidied up, left the old copy beside the deck. If the deck was then renamed, moved or deleted, the next start of a server made that old copy into the deck again under its old name. Now, when the record of the save was kept, which is the normal case, the old copy stays where it is, a read of the old name says it is only an older copy, and the next answer says where it is. If another server, or an older version of this one, saved the deck in the meantime, the next start keeps that newer backup instead of putting the older one over it.
- **Recovering from a stopped save touches only the deck's own files.** It moves or removes only the deck's old copy, this server's own temporary files and its staged backups, never another file that a damaged record of the save names. At start, the server puts back the decks on this computer before it answers and stops after about 5 seconds; it puts back the rest, and the decks on network shares, in the background, so a share that does not answer never holds it up. A change to one deck never waits on the record of another deck's save, and the record of a deck whose folder has been gone for a week is dropped. An old copy that another program held during a save is removed at the deck's next change after that program lets go of it, or kept and named in a notice when it holds the only copy of a version. At the next start of a server that may change files, or at the deck's next change, the backups a stopped save had staged go into place, unless later saves have already moved the backups on. Staged copies that no record of a save still needs are cleared at the deck's next change once they are an hour old.
- **A save stopped in its last instants finishes correctly on a deck that came by email or a download.** Such decks carry a Mark of the Web, and recovery took them for decks saved again since: the backup of the version before the last change did not go into place, and a notice wrongly said the deck was saved again, or that backup was dropped without a word. Recovery now checks the backups themselves and puts them in place exactly as the save would have.
- **A deck on a share that does not answer no longer slows anything down.** One record of a stopped save for a deck on a share that had gone away made every change to any deck, and the start, wait about 20 seconds. A change now never waits on another deck's record, and the start puts back decks on network shares in the background.
- **Finishing a stopped save keeps the version before the last change, or says why it cannot.** A backup that another program held could be thrown away, a backup that later saves had moved on from was dropped without a word, and an old copy could stay beside a deck for good with no notice. Now a backup that cannot go into place yet waits for the deck's next change, one with no slot left is let go with a notice, and an old copy that holds the only copy of a version is named in each run of the server until it is gone.
- **Recovery finds a deck under its 8.3 short name and other spellings of the same path.** A change or a read that named a deck by its 8.3 short name, or a save under another case, could leave a stopped save's old copy behind, report a deck as missing without saying where it was, or rename the deck's file to that case. Saves now use the path as Windows resolves it, and the record of each save keeps the deck's short name. This covers the 8.3 short name, another case, forward or back slashes, a `\\?\` prefix, a `..` step and a trailing dot. A save made through a `subst` or mapped drive letter and then changed under the real path is matched at the next start of the server.
- **`fit_text` keeps each shape's autofit setting and fits by one mechanism.** It used to rewrite the run sizes and also switch the shape to shrink text on overflow, so PowerPoint could shrink the text a second time while the answer said it fitted. A shape set to shrink text on overflow, by its own setting or its layout's, now gets the fit as that setting's font scale and keeps its run sizes. A shape set to resize to fit its text is fitted to the room it can grow into on the slide, and one that stays on the slide is left alone. Other text has its sizes rewritten. The answer names the setting, where it comes from and the mechanism used. A run already at or below `min_size` keeps its size, and a placeholder drawn in its layout's box is fitted too.
- **`validate` gives PowerPoint the time its deck needs.** The opens-clean check had a fixed 60 seconds, which a healthy deck of about 1,400 shapes could run past. The limit now grows with the deck's slides, shapes, notes pages and media, up to 300 seconds, and `opens_clean_time_limit` in the answer says how long and why. A check that runs out of time answers `opens_clean: null` and `timed_out: true`, with a note that it is a time limit, not a verdict on the deck.
- **A change that was saved is no longer reported as a failure.** When the answer to a change is larger than the output limit, long values are shortened and `page.note` says the change stands. The file, saved and backup fields and the slide the call reached are never shortened. Before, a call such as `set_theme_fonts` with a very long typeface saved the deck and then answered `LIMIT_EXCEEDED`.
- **Theme fonts refuse a typeface no installed font can have.** `set_theme_fonts` and `apply_brand` refuse a typeface longer than 31 characters, the Windows limit for a font name, before anything is written.
- **`create_snapshot` refuses a file that is empty or cut off, has a part whose checksum does not match, or whose `[Content_Types].xml` or `ppt/presentation.xml` is not readable XML, instead of keeping a permanent copy of it.** These checks read the file; they do not open it in PowerPoint. A password-protected deck is still copied whole once its file structure is complete.

If the layout has none or several matches, the call refuses and lists the placeholders present.

- **A deck with a click action that plays media can be saved.** PowerPoint writes that action with an empty relationship id (`r:id=""` with `action="ppaction://media"`). The save check read the empty id as a missing relationship and refused the save as a `dangling relationship id`; it now accepts it. Any other relationship id that points at nothing is still refused.

- **Line and fill settings are checked.** A key the tool does not understand is now refused by name. It used to be dropped without a word, which is how a requested arrowhead or a hidden border went missing. Keys that 1.2.3 accepted silently and 1.3.0 refuses: on a solid line, `opacity`, `transparency`, `colour`, `weight`, `thickness`, `style`, `compound`, `miter`, `cap_style`, `dash_style`, `dashStyle`, `arrow`, `headEnd`, `tailEnd`, `startArrow`, `endArrow`, `line`; beside `type: "none"` on a line, `width`, `color`, `alpha`, `dash`, `cap`, `join`, `head`, `tail`, `head_end`, `tail_end`, `start_arrow`, `end_arrow`; on a fill, `opacity`, `transparency`, `colour`, `fill`, `shade`, `pattern`, `image`, `gradient`, `angle`, `stops`, `radial`. Any other unknown key is refused too. The accepted keys for each kind are listed in the tool descriptions.
- Replacing a shape's text keeps the formatting nobody asked to change: colour, alignment, bullets, indent level and vertical anchor. It used to reset them, and on some shapes that left white text on a white box. The result lists what was preserved. When the old text mixed several formats, the new text takes the first run's formatting and the result says so.
- A replacement no longer carries a stale autofit shrink. The autofit mode is kept and the cached scale is cleared. PowerPoint does not recalculate that scale when it opens the file, so a replacement longer than the original can overflow its box; the result says the fit is unknown and names `fit_text`, and `check_layout` reports the overflow.
- `bold: false` and `italic: false` now turn the formatting off, including bold or italic inherited from the layout. They used to be ignored. `wrap: true` is written as well.
- A font set through `text_style` now applies to East Asian and complex-script text as well as Latin text.
- A line with `type: "none"` really has no border, even when the shape's style would paint a themed one, and `start_arrow` and `end_arrow` on a connector are kept.
- `set_shape` can give a placeholder that takes its position from the layout its first explicit position and size. `format_text` gains `anchor` and `wrap`. Inside `apply_edits` the vertical-anchor key is `text_anchor`, because `anchor` there already names the shape being edited.
- Long decks can be read to the end. Paged reads lead with `page` and `returned`, and `extract_text` takes `limit` and `offset`, so the hint it gives can be followed.
- `check_layout` sees what PowerPoint shows. Font sizes inherited from the placeholder, the layout or the master are read, and an autofit scale is applied before text is judged too small. Contrast is measured against what is really behind the text, including table cells that take their colours from a table style defined in the deck. When a colour cannot be determined (PowerPoint's built-in table styles are not stored in the file; pictures and gradients have no single colour) the finding is informational and never an error. Shapes that overlap inside a group are reported, tuned by `min_group_overlap_in` and `exclude_names`, which matches whole words in any script. A deck that was clean on 1.2.3 can report findings on 1.3.0.
- `audit_accessibility` and `set_reading_order` now see the position a placeholder inherits from its layout, so the reading order of a templated deck can come out differently, and more accurately, than before.
- The column tools accept `widths="fit"`, as their descriptions always said; `rescale` still works as another name for it, and the result reports `fit`.
- `get_workflows` has a new guide, `refresh-an-existing-deck`.
- The MCP Registry entry moves to the `io.github.KitchenSink4AI` namespace and is published from the release workflow.

### 1.2.3
- A deck mutation or a live PowerPoint session that runs longer than ten minutes keeps its lock. Both locks were previously broken on age alone even while the holding process was alive, which let a second writer into the same file and reopened the race the locks exist to close.
- A lock written by another machine is never reclaimed from this one. A PID number on a network share says nothing about a process on a different computer, so a foreign-host lock now makes the waiter wait and then refuse by name.
- Runtime hints and error messages no longer contain em dashes, which some terminals and log pipelines render as replacement characters.
- Eighteen tests that drive a real PowerPoint or LibreOffice now carry the `live` marker, so `-m "not live"` deselects them.
