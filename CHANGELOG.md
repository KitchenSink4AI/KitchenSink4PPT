### 1.3.1

KitchenSink4PPT 1.3.1 is a fix release shaped by a real 45-slide deck build, with safer validation, clearer refusals, and more control over text fitting and table layout.

- **A misspelled pack lock now fails closed.** `KS4P_PACK_POLICY` accepts only `auto` or `locked`. Any other value, including a typo such as `lockedd`, refuses startup with a clear message. An unrecognised value used to leave optional packs switchable. A correctly spelled `locked` behaves as before.
- `set_placeholder_text` keeps the formatting of the text it replaces: paragraph indents and spacing, bullets, default character formatting, and run formatting. Fields and line breaks keep their character formatting too. A level the caller states still wins; extra paragraphs take the last old paragraph's formatting; a mixed-format collapse is reported. Within a paragraph, runs whose hyperlinks disagree lose the link, and the result says so; a link shared by every run of that paragraph is kept. In `set_placeholder_text`, a `text=` line with no leading tab now returns the paragraph to the top outline level.
- Mouse-over hyperlinks on text now appear in hyperlink tools, remain intact when slides are copied, and are cleaned up when their target slide is deleted.
- Save validation refuses a text body with no paragraph before it can make the whole deck unreadable, and names the part and shape. The rule covers slide shapes, table cells, diagram text and chart text, and accepts paragraphs supplied through compatibility (`mc:AlternateContent`) branches. Empty placeholder text, agendas and speaker notes now leave one empty paragraph. When PowerPoint itself refuses a deck, `validate` reports `failed_slide_index`, `failed_slide_id`, `failed_shape_index` and `failed_shape_name` when it can locate the failure, looking inside groups and table cells; it does not walk notes, layouts, masters or chart internals. A PowerPoint that is busy or disconnects mid-check is reported as the application being blocked, not as a damaged file.
- Install the optional `metrics` extra to let `fit_text`, `get_autofit_state` and the `check_layout` overflow check measure installed-font character widths and wrap by word. Results report `method="font-metrics"` or `method="estimate"` and explain a fallback. Text with mixed formatting is measured run by run, and font collections are read by face. Character spacing is measured. When a run's font size, typeface, or indentation cannot be resolved with certainty, the result falls back to the estimate and states why. Measured widths carry a small safety margin, so the check errs toward reporting an overflow; with the extra installed, a deck that passed before can show new findings. Kerning and justification are not modelled, so render with `export_slide_images` before presenting.
- COM startup refusals such as `CO_E_NOTINITIALIZED` now use `APP_NOT_RUNNING` instead of `BAD_PARAMS` and name the startup fault. Apartment state is recorded, `powerpoint_status` reports `com_apartment`, and an uninitialised-apartment fault gets one bounded retry. The server never ends a PowerPoint process on this path; if one appeared during the failed start, the refusal says so and leaves it running. If the server cannot read the PowerPoint process list, it no longer assumes that it started PowerPoint, so it will not close an instance it only attached to. When PowerPoint was absent at entry and remains hidden with no presentation open at cleanup, the server quits the application; otherwise it closes its own presentations and leaves PowerPoint running. After a timeout, the server reports an observed PowerPoint process when available and does not force-end it; the operation may continue and finish after the response. A call that was still waiting for its turn when the caller gave up is abandoned and never runs, so a retry cannot repeat an edit. The field failure did not reproduce in eighteen attempts, and its cause remains unknown.
- `diagnose` explains how to finish the LibreOffice slide-image setup when `pdftoppm` is missing. Discovery now checks `KS4P_PDFTOPPM`, PATH and common install locations. The remedy remains to install poppler or use PowerPoint for slide images.
- `copy_presentation` now names a missing destination folder and tells the caller to create it or choose an existing folder. It does not create directories from a possibly mistyped path.
- `create_table` accepts `row_heights` and `col_widths` at creation. A complete list of inches resizes the table frame to the stated total, and the result reports the new size. With an `{index: inches}` dictionary, unnamed rows or columns share the space that remains. Invalid sizes and partial sizes that leave no room are refused with the arithmetic.
- `enable_tools` now says what to do when a client fixed its tool list at startup, and no longer claims a list change was sent when the packs were already on. Put a comma list of packs in `KS4P_MODE`, restart the app or session, and then start a new worker. Claude Code can instead enable packs in its main session before it starts workers. A locked policy still caps the surface.

### 1.3.0

Two defaults change in this release. Read the first two entries before you upgrade.

- **A deck created without a template is now widescreen (16:9).** It used to be 4:3. The bundled layouts are rescaled to the new canvas, so every placeholder sits where it should. To get the old shape, ask for it: `create_presentation(slide_size="4:3")`. `slide_size` accepts a fixed list of presets and refuses anything else. A deck built from a template keeps the template's own size, and giving `slide_size` together with a template is refused. `set_slide_size` changes the canvas without moving content, so it is not a way back to 4:3 on a new deck. The 16:10 preset resizes the layout boxes only; text sizes stay as they are.
- **Line and fill settings are checked.** A key the tool does not understand is now refused by name. It used to be dropped without a word, which is how a requested arrowhead or a hidden border went missing. Keys that 1.2.3 accepted silently and 1.3.0 refuses: on a solid line, `opacity`, `transparency`, `colour`, `weight`, `thickness`, `style`, `compound`, `miter`, `cap_style`, `dash_style`, `dashStyle`, `arrow`, `headEnd`, `tailEnd`, `startArrow`, `endArrow`, `line`; beside `type: "none"` on a line, `width`, `color`, `alpha`, `dash`, `cap`, `join`, `head`, `tail`, `head_end`, `tail_end`, `start_arrow`, `end_arrow`; on a fill, `opacity`, `transparency`, `colour`, `fill`, `shade`, `pattern`, `image`, `gradient`, `angle`, `stops`, `radial`. Any other unknown key is refused too. The accepted keys for each kind are listed in the tool descriptions.
- Replacing a shape's text keeps the formatting nobody asked to change: colour, alignment, bullets, indent level and vertical anchor. It used to reset them, and on some shapes that left white text on a white box. The result lists what was preserved. When the old text mixed several formats, the new text takes the first run's formatting and the result says so.
- A replacement no longer carries a stale autofit shrink. The autofit mode is kept and the cached scale is cleared. PowerPoint does not recalculate that scale when it opens the file, so a replacement longer than the original can overflow its box; the result says the fit is unknown and names `fit_text`, and `check_layout` reports the overflow.
- `bold: false` and `italic: false` now turn the formatting off, including bold or italic inherited from the layout. They used to be ignored. `wrap: true` is written as well.
- A font set through `text_style` now applies to East Asian and complex-script text as well as Latin text.
- A line with `type: "none"` really has no border, even when the shape's style would paint a themed one, and `start_arrow` and `end_arrow` on a connector are kept.
- `set_shape` can give a placeholder that takes its position from the layout its first explicit position and size. `format_text` gains `anchor` and `wrap`. Inside `apply_edits` the vertical-anchor key is `text_anchor`, because `anchor` there already names the shape being edited.
- Long decks can be read to the end. Paged reads lead with `page` and `returned`, and `extract_text` takes `limit` and `offset`, so the hint it gives can be followed.
- `check_layout` sees what PowerPoint shows. Font sizes inherited from the placeholder, the layout or the master are read, and an autofit scale is applied before text is judged too small. Contrast is measured against what is really behind the text, including table cells that take their colours from a table style defined in the deck. When a colour cannot be determined (PowerPoint's built-in table styles are not stored in the file; pictures and gradients have no single colour) the finding is informational and never an error. Shapes that overlap inside a group are reported, tuned by `min_group_overlap_in` and `exclude_names`, which matches whole words in any script. A deck that was clean on 1.2.3 can report findings on 1.3.0.
- `audit_accessibility` and `set_reading_order` now see the position a placeholder inherits from its layout, so the reading order of a templated deck can come out differently, and more accurately, than before.
- The column tools accept `widths="fit"`, as their descriptions always said; `rescale` still works as another name for it, and the result reports `fit`.
- `get_workflows` has a new guide, `refresh-an-existing-deck`.
- The MCP Registry entry moves to the `io.github.KitchenSink4AI` namespace and is published from the release workflow.

### 1.2.3
- A deck mutation or a live PowerPoint session that runs longer than ten minutes keeps its lock. Both locks were previously broken on age alone even while the holding process was alive, which let a second writer into the same file and reopened the race the locks exist to close.
- A lock written by another machine is never reclaimed from this one. A PID number on a network share says nothing about a process on a different computer, so a foreign-host lock now makes the waiter wait and then refuse by name.
- Runtime hints and error messages no longer contain em dashes, which some terminals and log pipelines render as replacement characters.
- Eighteen tests that drive a real PowerPoint or LibreOffice now carry the `live` marker, so `-m "not live"` deselects them.

### 1.2.2
- New `get_server_info` tool: ask the server what it is and it answers with the product and package name, the version you are connected to, the landing page, its sibling servers, the tool and test counts, and the packs you can switch on. Every count is read off the running server rather than remembered.
- The server now introduces itself by name in the instructions a client reads at connect, so an agent can tell you which product it is driving.

### 1.2.1
- The server moves to the same foundation library as its siblings (fastmcp 3), so all four KitchenSink servers now install together into one environment. Tiered loading is unchanged and re-verified over the wire: packs still switch mid-session and clients are still told the tool list changed.

### 1.2.0
- Every read is budgeted: one call can no longer flood a conversation, and anything left out is named with a continuation.
- Saves are up to three times faster and now preserve each media file's original compression exactly.
- Update notice: a weekly, disclosed check for newer releases, off with KS4P_UPDATE_CHECK=off.
- The install screen and info card are rewritten in plain language.
